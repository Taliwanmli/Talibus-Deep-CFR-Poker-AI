# v0.2 Reproducible Pipeline

The reproducible CPU pipeline is implemented and merged on `main`.

## Summary

Talibus now has a small CPU workflow that connects real traversal/sample
generation, fresh PyTorch training, ONNX export, and Rust model-only evaluation.
The workflow makes the system integration verifiable after documented setup
without CUDA, historical training buffers, or the released long-run model.

```bash
python training/deep_cfr/run_smoke.py
```

See [CPU Smoke Experiment](smoke.md) for exact prerequisites, outputs, observed
cost, and reproducibility limits.

## Changes Since v0.1

- Compact best-ring ONNX strategy and advantage artifacts, model specifications,

- Versioned experiment configuration and preparation manifests with portable
  resource roots, validated settings, Git/runtime evidence, and artifact hashes.
- Deterministic fresh per-network initialization, preserving ambient CPU RNG
  state and existing resume behavior.
- A bounded CPU smoke profile consumed by an executable wrapper around the
  existing training and Rust evaluation entry points.
- Checks for real sample consumption, optimizer work, changed checkpoint
  parameters, compatible ONNX tensor shapes, and completed Rust inference and
  simulator evaluation.
- Completed/failed execution manifests, structured results, stage status/logs,
  derived seeds, runtime-library identification, and generated/input hashes.
- Native ONNX Runtime discovery for macOS, Linux, and Windows package layouts.
- Python and Rust source/test CI, focused configuration/provenance/
  initialization/orchestration tests, and clearer reviewer-facing setup and
  architecture documentation.

## Verification Evidence

The full CPU workflow ran successfully in a newly installed Python environment
on macOS arm64. Two repeat runs produced identical retained traversal samples,
ONNX bytes, and checkpoint parameter tensors. Structured evaluation results
matched except for elapsed time. Both networks performed two optimizer steps
on samples generated by the run.

With cached Rust release builds, those runs took about 4 seconds and generated
about 1.8 MB each. A clean checkout with no Rust target directory completed in
about 14 seconds, including compilation, and produced matching sample/ONNX
hashes. The Rust release build directory used a separate 152 MiB; Python setup
and Cargo downloads are excluded from these measurements.

Verification also passed 53 training/configuration/provenance/orchestration
tests, 17 evaluation tests, Python source/dependency/CLI checks, and 61 Rust
tests plus formatting, Clippy, and required release builds. The existing
published strategy and advantage models matched their recorded hashes and were
exercised through Rust inference.

Normal CI checks source, CLIs, and unit tests. The full CPU experiment remains
an explicit integration check; CI badges in the README identify the actual
Python and Rust workflows on `main`.

## Preserved Research Evidence

The historical model package at
`artifacts/models/talibus-6max-longrun-opt-v1/` and controlled result pack at
`results/2026-04-03-6max-longrun-opt/` are preserved. Smoke outputs are separate
generated artifacts and do not replace those models or measurements.

## Limits

The tiny experiment validates engineering and reproducibility health. It does
not establish poker strength, general convergence, or production readiness.
Same-environment repeats do not guarantee cross-platform bitwise determinism.
Full historical long-run reproduction still requires omitted generated data,
checkpoints, and substantial compute. Python dependency versions are recorded
per run rather than fixed by a full dependency lock.

Published simulator metrics remain measurements against scripted opponents;
they do not demonstrate human-level or solver-level performance or real-money
profitability. Responsible-use boundaries remain unchanged.
